# Google Scholar publication sync

The Publications page renders `_data/scholar_publications.json` with year groups, author emphasis, venue details, and links to individual Google Scholar records. Profile: https://scholar.google.com/citations?user=Qv2IRBkAAAAJ&hl=en.

The local Codex automation `Sync Google Scholar publications` checks daily at 09:17 China Standard Time. Its automation ID is `sync-google-scholar-publications`. Keep the computer on and Codex running for scheduled checks. The updater uses only Python's standard library; the connected GitHub account publishes the verified JSON snapshot and triggers the normal GitHub Pages deployment. No additional paid API or browser session is required.

Google Scholar rejected the initial GitHub-hosted test with HTTP 403. The same request succeeded from the local computer. The failed cloud polling workflow has therefore been removed; the daily schedule lives in Codex, not in this repository. A durable script copy is saved under `outputs/scholar-publications/scripts/sync_scholar.py` in the local teaching project. Keep that copy in sync when changing this script.

One public profile request with pagesize=100 is made per run. The script does not crawl pagination, bypass challenges, or use proxies. It requires the expected profile name/ID, complete pagination state, valid metadata, unique IDs, and a nonempty list. Network failures, blocked responses, incomplete lists, and an unexpected loss of more than 20% of entries preserve the last valid snapshot and stop the update for review. If the profile eventually exceeds 100 entries or a large removal is intentional, review the source and adjust the import deliberately; do not disable these guards merely to make a failing run pass.

The automation reads the current JSON and file SHA from GitHub, seeds a scratch file, runs the updater once, and publishes only the verified JSON using that SHA to avoid overwriting concurrent changes. It verifies deployment after publishing. `checked_on` records the last successful daily check in China Standard Time; `updated_on` records the last metadata change. These are daily checks, not immediate push notifications. The page remains available with its last successful list if the computer is unavailable or Google Scholar blocks a request. The automation stays quiet when publication metadata is unchanged and reports new or corrected publications or failures requiring attention.

Run `python scripts/sync_scholar.py`, or pass `--html path/to/profile.html` for an already downloaded complete profile. Run `python -m unittest discover -s tests -p 'test_scholar_sync.py'` for the parser and preservation tests.
