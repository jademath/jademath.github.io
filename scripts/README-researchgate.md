# ResearchGate publication updates

The Publications page renders `_data/researchgate_publications.json`. ResearchGate profile `Yuliang-Wang-19` determines which publications belong in the list. Titles link to their ResearchGate records. Journal lines link to verified `https://doi.org/...` identifiers; arXiv preprints link to their `https://arxiv.org/abs/...` pages. Publisher/Crossref metadata supplies full author lists, journal details, and final issue years when ResearchGate has truncated authors, an upload date, or an online-first date.

The existing local Codex automation has been changed to **Sync ResearchGate publications**, every Monday at 09:17 China Standard Time. It retains the internal automation ID `sync-google-scholar-publications` to avoid duplicate schedules. Keep the computer on and Codex running. The daily Google Scholar task and Scholar data pipeline have been replaced.

ResearchGate rejected direct scripted requests during setup. Publicly indexed ResearchGate profile and publication pages were accessible through web retrieval. The weekly task uses this public research route, without login bypasses, proxies, or CAPTCHA workarounds. Indexed pages can lag the underlying profile. If the complete profile and its declared publication count cannot be verified, the task leaves the last successful list in place; it must not infer missing entries from an incomplete search result.

For each run, the task reads the current website JSON and its GitHub file SHA, compares the complete ResearchGate list, and verifies new or changed records against publisher/Crossref or arXiv metadata. It preserves the existing verified DOI and bibliographic details for unchanged articles. It creates a candidate JSON in a scratch directory and validates it using `scripts/update_researchgate_publications.py --input candidate.json --output current.json`. A durable copy of the script is stored under `outputs/researchgate-publications/scripts/` in the local teaching project. Keep that copy in sync with future script changes.

The validator checks profile identity, declared count, complete-source status, unique ResearchGate IDs and article links, full author lists containing the profile author, year ranges, HTTPS links, DOI/arXiv link forms, evidence URLs, and unexpected removals. It refuses updates that remove more than 20% of existing IDs even if replacement entries keep the total count unchanged. Only after all checks pass does it replace the scratch JSON atomically. These checks validate structure; bibliographic identity must still be verified against the source by the scheduled task.

The task publishes only the resulting JSON using the current GitHub file SHA, preserving concurrent website edits, and checks the normal GitHub Pages deployment. `checked_on` is the date of the last successful review of available public sources; `updated_on` is the date of the last bibliographic change. It stays quiet when publication metadata is unchanged and reports new or corrected publications or failures requiring attention.

Run the validation tests with `python3 -m unittest discover -s tests -p 'test_researchgate_publications.py'`. The repository contains no scheduled cloud scraper and needs no new API keys.
